# Phase 3 Enterprise Stabilization Report

## Architecture changes implemented

- Reduced `server.js` from a large monolith to an 18-line bootstrap.
- Extracted legacy app/routing code to `src/routes/legacyRoutes.js`.
- Removed runtime duplicate route replacement/patching.
- Statically removed duplicate route definitions, then verified zero duplicate method/path pairs through `npm run routes:inventory`.
- Added structured JSON logging through `src/utils/logger.js`.
- Added request id correlation through `src/middleware/requestContext.js`.
- Added transactional helper in `src/utils/db.js`.

## Database and transaction safety

Implemented transaction helper:

- `src/utils/db.js` → `withTransaction(pool, callback)`.

Transactional write areas:

- Attendance-drop automation: SMS log writes + automation log write.
- Grade-drop automation: SMS log writes + automation log write.
- Counselor-risk automation: management SMS log writes + automation log write.
- Counseling session creation: session insert + related request status update.
- Announcement summary/SMS automation: recipient SMS logs + automation log write.

AI generation is intentionally performed before transaction blocks so MySQL locks are not held during external provider latency.

## AI hardening implemented

- Backend-only GapGPT client using `AI_API_BASE_URL`, `AI_API_KEY`, `AI_DEFAULT_MODEL`.
- Timeout handling.
- Retry logic.
- Safe provider error redaction.
- Prompt size limiter.
- Max response token guard.
- Role-specific system prompt templates.
- Structured output mode for admin analytics.
- Per-minute in-memory limiter.
- Per-user daily quota backed by `ai_requests_log`.
- AI latency logging in structured logs.
- AI usage logging in `ai_requests_log`.

## SMS hardening implemented

- Provider-agnostic adapters: `generic_json`, `form_post`.
- Iranian phone validation and normalization to `+989xxxxxxxxx`.
- Duplicate suppression using `sms_logs.message_hash`.
- Per-user SMS daily limit backed by `sms_logs`.
- Global SMS per-minute limit.
- Provider circuit breaker after repeated failures.
- Retry logic and timeout handling.
- Structured provider error classification.
- SMS latency logging.
- SMS logs in `sms_logs`.

## Query and performance hardening

- Added/verified indexes documented in `PERFORMANCE_NOTES.md`.
- Added pagination to Phase 3 high-volume list endpoints:
  - `GET /api/v1/sms/logs?page=&limit=`
  - `GET /api/v1/counselor/requests?page=&limit=`
  - `GET /api/v1/counselor/sessions?page=&limit=`
- New endpoints use prepared-statement parameters.
- Numeric pagination is bounded and sanitized.

## Security review

Documented in `SECURITY_REVIEW.md`.

Key findings:

- JWT validation remains backend-enforced.
- New sensitive endpoints have role guards.
- Parent/teacher ownership checks are enforced for new sensitive flows.
- Counselor private notes are not sent in SMS notifications.
- AI/SMS secrets are server-only environment variables.
- Legacy routes still need a gradual controller extraction and field allowlist pass before a high-stakes public deployment.
